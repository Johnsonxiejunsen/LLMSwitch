# llm-cost v1 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** claude-tools 公开仓新增 `llm-cost` 插件——通用 LLM 使用成本计算 skill(单价注册表×token 分档纯函数内核 + 手报/文件/SQL/余额四数据源 + report 默认视图)。

**Architecture:** 单文件 python 脚本(stdlib + 可选 pymysql)承载内核与 CLI; 数据全部经"标准行"dict 汇入内核; SQL 源/余额/key 全部来自本地配置 `~/.claude/llm-cost/config.json`(仓内只有模板); 价格注册表仓内预置 + 本地覆盖合并。

**Tech Stack:** Python ≥3.9(纯 stdlib; pymysql 可选)、unittest、Claude Code plugin(skill 形态)。

**Spec:** `D:\program\claude-tools\llm-cost\docs\features\llm-cost\specs\llm-cost.md`(v1.1, 本 plan 一切口径以 spec 为准)

## Global Constraints

- 公开仓卫生: 全部随仓文件零内网 IP/密钥/内部系统名; 交付前跑 spec 判据⑦ grep 门 + 人工通读
- 金额一律 `Decimal`; prices.json 载入 `json.load(..., parse_float=Decimal)`; 展示单笔 4 位/汇总 2 位
- 默认 token 口径: `input_tokens 已含 cache hit`; `hit_included_in_input=false` 切 Anthropic 形态
- 退出码: `0`=至少一源成功; `1`=用法/业务错误(含 calc 未知模型/文件不存在/格式错/配置 schema 错); `2`=report 无任何成功源。**argparse 用法错误默认 exit 2, 必须子类化 error() 改 exit 1**
- 占位符仅对 `{start_date}`/`{end_date}`/`{days}` 三 token 字面 replace, 其余大括号原样保留; `start=今日−(days−1)`、`end=今日+1`(YYYY-MM-DD 本地时区)
- 超时: SQL connect ≤5s / read ≤10s; balance HTTP ≤5s; 超时=skipped 不挂死
- 输出中文; `--json` 键名=公开契约(spec §3.4 骨架)
- git: 本交付用户已授权 commit+push; 每任务一 commit, push 前亮清单等令牌

## Review Focus

1. **Anthropic 口径行**(input 不含 cache_read): `hit_included_in_input=false` 时 hit=cache_hit、miss=input_tokens——错走默认口径低报 62.5% → Task 2 测试钉死
2. **DATETIME 边界**: `>= {start_date} AND < {end_date}` 必须含今日全段(end=今日+1) → Task 3 测试(start/end 相对"今日"的差值断言)
3. **query 内字面大括号**(JSON 函数/未知 `{var}`): 只换三个 token, 其余原样 → Task 3 测试
4. **聚合中未知模型**: file/sql 跳过+计数+exit 0; calc 未知模型 exit 1——两种相反行为都存在且各归其位 → Task 5 测试
5. **全源失败 vs 零消费**: report 全 skipped → exit 2; 成功但 ¥0 → exit 0; `--json.skipped[]` 可判别 → Task 5 测试
